How saving works

Local saves are automatic. Every change you make to a case is written immediately to this browser (under localStorage). Closing the tab, rebooting your laptop — your work stays. There is no "Save" button to forget.

Sharing with colleagues is manual. To stay on the same state as the rest of the team, you exchange a single cdse.json file on the CDSE network drive. Workflow: Import first when you sit down (pulls in everyone else's edits), make your changes, then Export to publish your version back to the same file.

What the JSON file contains. Every case with every field, plus a revision number and the name of who saved last. No medical opinion, no machine learning, no cloud — just a structured snapshot of the database that any future tool (the planned Node + SQLite backend, an Excel export, a backup) can read. Each export overwrites the previous file.

If two people edit at the same time, the app detects it on the next Import and pops a Sync conflict modal. You then choose: keep your version (and overwrite the file next), or discard yours and apply the remote one. No silent data loss.

How to set this up on a network drive
  1. Pick a single shared folder everyone can read/write (e.g. \\cdse-server\statistik\).
  2. On every browser: in Firefox settings, set the default download folder to that shared folder.
  3. Click Export sync file — Firefox saves cdse.json straight onto the drive (it will offer to replace the existing file).
  4. Colleagues click Import sync file and pick cdse.json from the same drive.
  5. Always import first when you sit down; export when you're done editing.
Excel backup

A timestamped cdse-backup-YYYY-MM-DD-HHMM.csv snapshot that opens directly in Excel on double-click. Generated automatically every time you Export the sync file (above), or on demand here. Keep these accumulating in a backups/ sub-folder on the network drive — they are your disaster-recovery copies.
